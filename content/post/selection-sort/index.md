## 核心思想

选择排序的思路非常直白：**每一趟从未排序的部分里选出最小的数，放到已排序部分的末尾。**

1. 数组分成两部分：左边是已排序区，右边是未排序区。
2. 每一趟在未排序区里找最小值，和未排序区的第一个元素交换。
3. 已排序区扩大一格，重复直到整个数组有序。

## 实现原理
1. 设置变量 i，表示当前要确定的位置，排序开始时：i=0。
2. 在 [i, size-1] 这段未排序区里找最小的元素
    - 2.1 默认当前位置的数最小，记录下标 minIdx=i。
    - 2.2 用 j 从 i+1 扫描到 size-1，如果 array[j] < array[minIdx]，就更新 minIdx=j。
    - 2.3 扫描结束后，minIdx 就是未排序区最小值的位置。
    - 2.4 如果 minIdx != i，就把 array[i] 和 array[minIdx] 交换；相等则说明已经在正确位置，不用交换。
3. i++，已排序区扩大一格，重复第 2 步。
4. 当 i 走到 size-2 时，剩下最后一个元素一定是最大的，不用再处理。
5. 最终就会得到排序好的数组。

## C++ 实现

```cpp
#include <vector>
#include <algorithm>
using namespace std;

void selectionSort(vector<int> &nums) {
    int n = nums.size();
    for (int i = 0; i < n-1; ++i) {
        int key = i;
        for (int j = i+1; j < n; ++j) {
            if (nums[j] < nums[key]) {
                key = j;
            }
        }
        swap(nums[i], nums[key]);
    }
}
```

## 过程示例

以 `[64, 25, 12, 22, 11]` 为例，`|` 左边是已排序区：

```text
初始:     | 64  25  12  22  11
i=0 选 11: 11 | 25  12  22  64    （11 与 64 交换）
i=1 选 12: 11  12 | 25  22  64    （12 与 25 交换）
i=2 选 22: 11  12  22 | 25  64    （22 与 25 交换）
i=3 选 25: 11  12  22  25 | 64    （25 本身就最小，不用交换）
结束:     11  12  22  25  64
```

## 复杂度

| 情况 | 时间 | 说明 |
| --- | --- | --- |
| 最好 / 平均 / 最坏 | O(n²) | 不管数据什么样，比较次数都是 n(n-1)/2 |
| 空间 | O(1) | 原地排序，只用几个临时变量 |
| 交换次数 | 最多 n-1 次 | 这是它相对冒泡排序的优点 |

## 面试常问

**1. 选择排序稳定吗？**

不稳定。因为它是「隔着很远交换」的。比如 `[5a, 5b, 2]`：第一趟选出 2，和最前面的 5a 交换，变成 `[2, 5b, 5a]`，两个 5 的相对顺序变了。

**2. 数据已经有序，它会变快吗？**

不会。每一趟都要把后面扫完才能确定最小值，所以最好情况也是 O(n²)。这点和插入排序、带优化的冒泡排序不同，它们遇到有序数据可以提前结束。

**3. 它有什么优点？**

交换次数最少，最多 n-1 次。如果「写入/交换」的代价特别高（比如写闪存），选择排序反而有优势。

**4. 怎么让它稳定？**

不用交换，改成把最小值「插入」到前面，中间的元素依次后移，就能保持相等元素的顺序，但代价是要多做移动操作。

**5. 和冒泡、插入排序怎么比？**

| | 选择 | 冒泡 | 插入 |
| --- | --- | --- | --- |
| 平均时间 | O(n²) | O(n²) | O(n²) |
| 有序时 | O(n²) | O(n)（带优化） | O(n) |
| 稳定性 | 不稳定 | 稳定 | 稳定 |
| 交换次数 | 最少 | 最多 | 中等 |

## 小结

选择排序简单、好写、交换少，但永远是 O(n²)，数据量大时不实用，面试里主要考的是：**写得出来、说得清稳定性、能和冒泡/插入对比。**
