> MLA 指 **Multi-head Latent Attention**（多头潜在注意力），由 DeepSeek 在 DeepSeek-V2 中提出（论文：*DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model*，arXiv 2405.04434），后续的 DeepSeek-V3 等模型也沿用了它。本文的公式和数据以这篇论文为准。

## 核心思想

MLA 要解决的是大模型推理时 **KV Cache 太大**的问题。它的做法一句话概括：**不直接缓存每个头的 K 和 V，而是把它们压缩成一个很小的“潜在向量”，只缓存这个向量，用的时候再还原。**

1. 标准注意力要缓存每个 token、每一层、每个头的 K 和 V，显存开销随序列长度线性增长。
2. MLA 先把输入 \(h_t\) 压缩成低维向量 \(c_t^{KV}\)，K 和 V 都从它还原，缓存时只存 \(c_t^{KV}\)。
3. 位置编码 RoPE 和这种压缩方式冲突，于是 MLA 额外拆出一小块专门携带位置信息的向量，也一起缓存。
4. 最终每个 token 每层只缓存几百个数，而不是几万个数，效果还不比 MHA 差。

## 背景：为什么要关心 KV Cache

大模型生成文本是**一个 token 接一个 token** 往外吐的。每生成一个新 token，都要和前面所有 token 做注意力，而前面 token 的 K 和 V 在之前已经算过了。为了不重复计算，就把它们存起来，这就是 KV Cache。

标准多头注意力（MHA）里，每个 token 每层要缓存的元素个数是：

$$
2 \times n_h \times d_h
$$

其中 \(n_h\) 是注意力头数，\(d_h\) 是每个头的维度，2 表示 K 和 V 各一份。乘上层数 \(l\) 就是每个 token 的总缓存。

以 DeepSeek-V2 的结构为例（\(n_h=128\)，\(d_h=128\)，\(l=60\)），假如用 MHA，每个 token 要缓存 \(2\times128\times128\times60 = 1{,}966{,}080\) 个元素。按 BF16（每个元素 2 字节）估算，一个 token 约 3.75 MiB，**128K 长度的单条序列就需要约 480 GiB**，远远超过一张显卡的显存。

KV Cache 会带来两个直接的问题：

- **显存**：缓存太大，能同时服务的请求数（batch size）和最大序列长度都被限制。
- **带宽**：解码阶段每一步都要把整个缓存从显存读一遍，读取速度成了瓶颈。

## 从 MHA、MQA、GQA 到 MLA

在 MLA 之前，业界已经有两种压缩 KV Cache 的办法：

- **MQA（Multi-Query Attention）**：所有头共用同一份 K 和 V，缓存最小，但效果下降明显。
- **GQA（Grouped-Query Attention）**：头分成 \(n_g\) 组，组内共用 K 和 V，是效果和缓存之间的折中。

它们的思路都是“**让多个头共享**”，缓存降下来的同时，表达能力也被削弱了。MLA 换了一条路：每个头仍然有自己的 K 和 V，但它们都是从**同一个低维向量**还原出来的，也就是“**低秩压缩**”而不是“共享”。

下面是论文里对每个 token 的缓存量对比（元素个数，\(l\) 为层数）：

| 注意力机制 | 每个 token 的 KV Cache | 论文给出的能力评价 |
| --- | --- | --- |
| MHA | \(2 n_h d_h l\) | 强 |
| GQA | \(2 n_g d_h l\) | 中等 |
| MQA | \(2 d_h l\) | 弱 |
| MLA | \((d_c + d_h^R)\, l \approx 4.5\, d_h l\) | 更强 |

其中 \(d_c\) 是 KV 的压缩维度，\(d_h^R\) 是解耦 RoPE 部分的维度。DeepSeek-V2 里 \(d_c = 4 d_h\)，\(d_h^R = d_h / 2\)，所以缓存量等价于只有 **2.25 组**的 GQA，但效果却比 MHA 还好。

## 实现原理
1. 对 K 和 V 做低秩联合压缩
    - 1.1 下投影：把输入 \(h_t\)（维度 \(d\)）压缩成低维潜在向量 \(c_t^{KV}\)（维度 \(d_c\)，远小于 \(n_h d_h\)）。
    - 1.2 上投影：用两个矩阵 \(W^{UK}\)、\(W^{UV}\) 把 \(c_t^{KV}\) 分别还原成所有头的 K 和 V。
    - 1.3 推理时只缓存 \(c_t^{KV}\)，不缓存还原后的 K 和 V。
2. 对 Q 也做低秩压缩
    - 2.1 同样先下投影成 \(c_t^{Q}\)，再上投影成所有头的 Q。
    - 2.2 这一步**不能减少 KV Cache**，目的是减少训练时的激活显存。
3. 解耦 RoPE，单独携带位置信息
    - 3.1 额外生成一份带 RoPE 的查询 \(q_t^R\)，每个头一份。
    - 3.2 额外生成一份带 RoPE 的键 \(k_t^R\)，**所有头共享一份**。
    - 3.3 \(k_t^R\) 也需要缓存。
4. 拼接并计算注意力
    - 4.1 每个头的 Q 是“压缩还原的部分”和“RoPE 部分”拼接起来：\([q_{t,i}^C;\, q_{t,i}^R]\)。
    - 4.2 每个头的 K 同样拼接：\([k_{t,i}^C;\, k_t^R]\)。
    - 4.3 用拼接后的 Q、K 算注意力分数，再对 V 加权求和，最后经过输出矩阵 \(W^O\)。
5. 每个 token 每层最终只缓存 \(c_t^{KV}\) 和 \(k_t^R\)，一共 \(d_c + d_h^R\) 个元素。

## 公式汇总

**低秩压缩 K、V：**

$$
c_t^{KV} = W^{DKV} h_t,\qquad k_t^{C} = W^{UK} c_t^{KV},\qquad v_t^{C} = W^{UV} c_t^{KV}
$$

**低秩压缩 Q：**

$$
c_t^{Q} = W^{DQ} h_t,\qquad q_t^{C} = W^{UQ} c_t^{Q}
$$

**解耦 RoPE：**

$$
q_t^{R} = \mathrm{RoPE}(W^{QR} c_t^{Q}),\qquad k_t^{R} = \mathrm{RoPE}(W^{KR} h_t)
$$

**拼接，得到第 \(i\) 个头的 Q 和 K：**

$$
q_{t,i} = [\,q_{t,i}^{C};\, q_{t,i}^{R}\,],\qquad k_{t,i} = [\,k_{t,i}^{C};\, k_t^{R}\,]
$$

**注意力输出：**

$$
o_{t,i} = \sum_{j=1}^{t} \mathrm{Softmax}_j\!\left(\frac{q_{t,i}^{\top} k_{j,i}}{\sqrt{d_h + d_h^R}}\right) v_{j,i}^{C},\qquad u_t = W^{O}\,[\,o_{t,1};\, o_{t,2};\, \dots;\, o_{t,n_h}\,]
$$

符号说明：\(W^{D*}\) 是下投影矩阵，\(W^{U*}\) 是上投影矩阵；\(c_t^{KV}\) 和 \(k_t^R\) 是推理时需要缓存的两部分。

## 两个关键细节

### 矩阵吸收：为什么只缓存 \(c_t^{KV}\) 就够了

乍一看，只缓存压缩向量，每次还得用 \(W^{UK}\)、\(W^{UV}\) 把所有历史 token 的 K 和 V 都还原出来，岂不是更慢？MLA 的办法是**不还原**，利用矩阵乘法的结合律，把上投影矩阵“吸收”进别的矩阵里。

以注意力分数中不含位置编码的那一部分为例（第 \(i\) 个头）：

$$
q_{t,i}^{C\top} k_{j,i}^{C} = (W_i^{UQ} c_t^{Q})^{\top}(W_i^{UK} c_j^{KV}) = c_t^{Q\top}\,\big(W_i^{UQ\top} W_i^{UK}\big)\, c_j^{KV}
$$

括号里的矩阵只和模型参数有关，可以**提前算好**。这样算分数时，直接拿 \(c_t^{Q}\) 和缓存里的 \(c_j^{KV}\) 做运算就行，不需要把 \(k_{j,i}^C\) 还原出来。

V 这边同理：注意力输出是对 V 加权求和，而 \(W^{UV}\) 是线性的，所以

$$
\sum_j a_j \, W^{UV} c_j^{KV} = W^{UV} \sum_j a_j \, c_j^{KV}
$$

可以先对 \(c_j^{KV}\) 加权求和，再乘 \(W^{UV}\)，而 \(W^{UV}\) 又能和后面的输出矩阵 \(W^O\) 合并成一个矩阵。论文里的说法是：推理时 \(W^{UK}\) 可以吸收进 \(W^{Q}\)，\(W^{UV}\) 可以吸收进 \(W^{O}\)，所以我们**根本不需要把 K 和 V 算出来**。

### 为什么要解耦 RoPE

RoPE 是对 Q 和 K 分别按它们的位置旋转，两者点积后只剩**相对位置**的影响。如果直接给压缩还原出来的 K 加 RoPE，上面的吸收就做不了了：

$$
(R_t\, W^{UQ} c_t^{Q})^{\top}(R_j\, W^{UK} c_j^{KV}) = c_t^{Q\top} W^{UQ\top}\, R_{j-t}\, W^{UK} c_j^{KV}
$$

两个上投影矩阵中间夹了一个旋转矩阵 \(R_{j-t}\)，它取决于当前 token 和每个历史 token 的相对距离，每个位置都不一样，没法提前合并。不吸收的后果是：每生成一个 token，都得把整个前缀的 K 重新算一遍，推理效率大打折扣。

MLA 的解决办法就是**解耦**：把“内容”和“位置”分开处理。

- 内容部分走压缩路径，可以吸收。
- 位置部分单独拿一小块维度（\(d_h^R\)）出来加 RoPE，每个头一份 \(q^R\)，所有头共享一份 \(k^R\)，这部分直接缓存，不压缩。

代价就是缓存里多了 \(d_h^R\) 个元素，但这个量很小（DeepSeek-V2 里是 64）。

## 数字上的对比

DeepSeek-V2 的 MLA 配置（论文中的设置）：

| 参数 | 数值 |
| --- | --- |
| 层数 \(l\) | 60 |
| 隐藏维度 \(d\) | 5120 |
| 注意力头数 \(n_h\) | 128 |
| 每个头的维度 \(d_h\) | 128 |
| KV 压缩维度 \(d_c\) | 512 |
| Q 压缩维度 \(d_c'\) | 1536 |
| 解耦 RoPE 的每头维度 \(d_h^R\) | 64 |

按这套结构，下面是几种注意力机制每个 token 缓存量的估算（BF16，每个元素 2 字节，单条序列，GQA 取 8 组；这是我按公式算的估算值，不是论文原表）：

| 机制 | 每个 token 的元素数 | 每个 token 的大小 | 128K 序列的大小 |
| --- | --- | --- | --- |
| MHA | 1,966,080 | 3.75 MiB | 480 GiB |
| GQA（8 组） | 122,880 | 240 KiB | 30 GiB |
| MQA | 15,360 | 30 KiB | 3.75 GiB |
| MLA | 34,560 | 约 67.5 KiB | 约 8.4 GiB |

可以看到，MLA 的缓存比 MHA 小了两个数量级，比 GQA（8 组）还小，只比 MQA 略大。而按论文的结论，它的效果却不输甚至超过 MHA。

## 论文里的实验结论

- **MLA 对比 MHA**：论文附录用两种规模的 MoE 模型（约 16B 和约 250B 参数）做了对比，在四个较难的基准上，MLA 的表现比 MHA 更好，同时 KV Cache 只需要 MHA 的 14%（小模型）和 4%（大模型）。
- **MHA 对比 GQA、MQA**：论文还用 7B 稠密模型比较过，MHA 在这些基准上明显优于 GQA 和 MQA，说明单纯靠共享来压缩缓存是会损失效果的。
- **整体指标**：DeepSeek-V2 相对 DeepSeek 67B，KV Cache 减少 93.3%，最大生成吞吐提升到 5.76 倍。这是整个模型的结果，实际部署时还叠加了 FP8 权重和平均约 6 bit 的 KV Cache 量化等工程优化，并不全是 MLA 一个设计的功劳。

## 面试常问

**1. MLA 和 GQA、MQA 的本质区别是什么？**

GQA、MQA 是让多个头**共享**同一份 K 和 V，信息被硬性合并了。MLA 里每个头仍然有自己独立的 K 和 V（因为每个头有各自的上投影矩阵），只是它们都来自同一个低维的潜在向量，是**低秩**而不是共享，所以表达能力损失更小。

**2. MLA 为什么能减少 KV Cache？**

因为缓存的不再是所有头的 K 和 V（共 \(2 n_h d_h\) 个元素），而是一个维度为 \(d_c\) 的潜在向量，加上一小块 \(d_h^R\) 维的位置向量。

**3. 为什么要解耦 RoPE？**

RoPE 的旋转矩阵会夹在 Q 的上投影和 K 的上投影之间，破坏矩阵吸收，导致推理时必须反复还原历史 K。解耦后，位置信息由独立的一小块向量携带，内容部分仍然可以吸收。

**4. 为什么 Q 也要压缩？它能减少 KV Cache 吗？**

不能。压缩 Q 是为了降低训练时的激活显存，和 KV Cache 无关。

**5. MLA 有什么代价？**

- 结构更复杂：多了几组投影矩阵，还要额外处理解耦的 RoPE，论文里还在压缩向量后加了 RMSNorm。
- 实现门槛更高：要发挥出吸收之后的优势，通常需要专门优化过的推理实现。
- 计算量的变化：从公式看，吸收之后每个头做点积的维度变成了 \(d_c + d_h^R\)，计算量比展开成普通多头更大。不过解码阶段的瓶颈主要是读 KV Cache 的带宽，而不是算力，所以整体依然划算。这是我对公式的理解，不是论文里的原话。

**6. MLA 能不能和量化等其他优化叠加？**

可以，它们作用在不同层面。论文里实际部署的 DeepSeek-V2 就同时用了 MLA 和 KV Cache 量化。

## 小结

- **核心**：把 K、V 压缩成低维潜在向量再缓存，用时再还原，每个 token 每层只缓存 \(d_c + d_h^R\) 个元素。
- **两个关键设计**：矩阵吸收让推理时不用真的还原 K 和 V；解耦 RoPE 解决位置编码和压缩互相冲突的问题。
- **效果**：缓存量相当于只有 2.25 组的 GQA，而论文中的效果不输 MHA。
- **面试重点**：它和 GQA、MQA 的区别（低秩而非共享）、为什么要解耦 RoPE、矩阵吸收是怎么回事。
