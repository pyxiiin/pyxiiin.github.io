## 核心思想

堆排序利用**堆**这种数据结构：先把数组整理成一个大顶堆，再不断把堆顶（当前最大值）换到数组末尾，然后重新整理剩下的部分。

1. 大顶堆：每个节点的值都不小于它的两个孩子，所以堆顶一定是最大值。
2. 用数组存堆：下标为 i 的节点，左孩子是 2i+1，右孩子是 2i+2，父节点是 (i-1)/2。
3. 每次把堆顶换到末尾，末尾就多确定了一个最大值；堆的范围缩小一格，再把新的堆顶「下沉」，恢复大顶堆。

## 实现原理
1. 设置变量 n=size，表示当前堆的大小。
2. 建堆：把整个数组调整成大顶堆
    - 2.1 从最后一个非叶子节点开始，即 i=n/2-1。
    - 2.2 对 i 做一次「下沉」，让它不小于自己的孩子。
    - 2.3 `i--` 往前走，直到 i=0，整个数组就是大顶堆。
3. 排序：反复取出堆顶
    - 3.1 把堆顶 array[0] 和当前堆的最后一个元素 array[end] 交换，array[end] 就是最终位置。
    - 3.2 堆的大小减 1，即 end 前移一格。
    - 3.3 对新的堆顶 array[0] 做一次「下沉」，恢复大顶堆。
    - 3.4 重复 3.1-3.3，直到堆里只剩一个元素。
4. 「下沉」的过程：
    - 4.1 比较当前节点 i 和它的左右孩子，找出三者中最大的，记为 largest。
    - 4.2 如果 largest 就是 i，说明已经满足堆的性质，停止。
    - 4.3 否则交换 array[i] 和 array[largest]，让 i=largest，继续往下比较。
5. 最终就会得到从小到大排序好的数组。

## C++实现
```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

void heap_max(vector<int> &nums, int start, int end) {
    int parent = start;
    int child = parent * 2 + 1;
    while (child < end) {
        if (child + 1 < end && nums[child+1] > nums[child]) {
            child++;
        }
        if (nums[parent] > nums[child]) {
            return;
        } else {
            swap(nums[parent], nums[child]);
            parent = child;
            child = parent * 2 + 1;
        }
    }

    return;
}

void heap_sort(vector<int> &nums) {
    int n = nums.size();
    for (int i = n/2-1; i >= 0; --i) {
        heap_max(nums, i, n);
    }

    for (int i = n-1; i > 0; --i) {
        swap(nums[0], nums[i]);
        heap_max(nums, 0, i);
    }
}
```

## 复杂度

| 情况 | 时间 | 说明 |
| --- | --- | --- |
| 建堆 | O(n) | 看起来是 n 次下沉，实际大部分节点离叶子很近，总代价是 O(n) |
| 排序 | O(n log n) | 要取 n-1 次堆顶，每次下沉最多 log n 层 |
| 最好 / 平均 / 最坏 | O(n log n) | 不受数据分布影响，没有快排那种最坏 O(n²) |
| 空间 | O(1) | 原地排序，只用几个临时变量 |

## 面试常问

**1. 堆排序稳定吗？**

不稳定。堆顶和末尾元素「隔着很远交换」，相等元素的相对顺序可能被打乱。比如 `[2a, 2b, 1]`：建堆后堆顶是 2a，换到末尾会跑到 2b 的后面。

**2. 建堆为什么是 O(n)，不是 O(n log n)？**

建堆是从下往上下沉：最底层一半的节点是叶子，不用动；倒数第二层的节点最多下沉 1 层，再往上最多下沉 2 层……层数越高节点越少，把「节点数 × 下沉层数」加起来，结果是 O(n)。

**3. 为什么实际中堆排序常常比快排慢？**

虽然堆排序最坏也是 O(n log n)，但它访问数组时在父子节点之间大幅跳跃，缓存命中率差；而快排的分区是顺序扫描，对缓存更友好。所以平均情况下快排的常数更小。

**4. 堆排序和快排、归并怎么选？**

| | 堆排序 | 快速排序 | 归并排序 |
| --- | --- | --- | --- |
| 最坏时间 | O(n log n) | O(n²) | O(n log n) |
| 空间 | O(1) | O(log n) | O(n) |
| 稳定性 | 不稳定 | 不稳定 | 稳定 |
| 特点 | 最坏有保证且原地 | 平均最快 | 稳定，适合链表 |

**5. 找前 K 大的数，用堆怎么做？**

不需要全部排序。维护一个大小为 K 的小顶堆，遍历数组：堆没满就直接放入；堆满了，如果新元素比堆顶大，就替换堆顶并下沉。遍历完，堆里就是前 K 大，时间 O(n log K)。C++ 里可以直接用 `priority_queue`。

## 小结

- **核心**：先建大顶堆，再反复把堆顶换到末尾并下沉，每次确定一个最大值。
- **两个操作**：建堆是 O(n)，每次取堆顶并下沉是 O(log n)，整体 O(n log n)。
- **特点**：最坏也是 O(n log n)、原地排序，但不稳定，缓存表现不如快排。
- **面试重点**：建堆为什么是 O(n)、堆排序为什么不稳定，以及用小顶堆求 Top-K。
